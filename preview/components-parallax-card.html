Behavior contract
themeRequired modifier: eu-parallax-card--sky or eu-parallax-card--field. A new artwork is a new --{theme} block setting --eu-parallax-card-bg / -shade (RGB triplets) and the art of __sky, both __roll pseudo-elements and any scenery plate — from PNGs in assets/parallax-card/{theme}/ (as sky does) or from gradients with no asset at all (as field does, which also switches the cloud bands off).
sceneryRender <div class="eu-parallax-card__plate" data-plate="1..8" aria-hidden="true"> between __clouds--near and __shine, ALWAYS all eight and in order, whatever the theme — they are numbered, not named, so artwork stays a pure CSS change. Each is display:none until a theme places it; sky places none, and field places none either — it DRAWS its scenery instead (see canvas below). A theme sets per plate: inset + width, the art, and its depth through --eu-parallax-card-plate-x / -y. The art is EITHER a background-image PNG with an aspect-ratio matching its pixel size (a background carries no intrinsic ratio) OR gradients with an explicit height. Depths climb with the stack, and plates overhang the card on every side so parallax never swings a hard edge into view — note that a plate whose art fades out at the top (a mask-image) must ALSO be anchored past the card's bottom edge, because its own bottom stays a hard cut and shows as a seam across the scene.
canvasA theme whose scenery is DRAWN rather than painted takes <canvas class="eu-parallax-card__canvas" aria-hidden="true"> as the FIRST child of __scene — it is the backdrop, so the shine and the scrim still sit over it. The system styles that box and nothing else: no JavaScript ships from here, so the consumer owns the renderer and mounts the canvas ONLY when it has one (a theme name must not be able to buy a WebGL context and a frame loop for a surface that never draws). A missing context — an old browser, blocked WebGL, jsdom under test — is an ordinary outcome and not an error: the card falls back to its plain painted self. field is the theme that draws; its renderer is the Outpost app's app/components/catalog/dock-hero.ts, ported from that site's charging-dock hero.
openerA drawn theme whose model has MOVING PARTS (the charging dock's six leaves) takes <label class="eu-parallax-card__opener"> — two __opener-end captions around an <input type="range" class="eu-parallax-card__opener-range"> — OUTSIDE __card, beside the toggle and the pager, so it does not tilt with the scene it controls. The consumer keeps it disabled until its renderer exists: a slider that moves nothing is a lie, and without WebGL it never enables at all. Set aria-valuetext so it speaks "42 percent open" rather than "42". Render it only for an entry that HAS something to open — most cards never show one.
pagingPrev/next wrap around: ((i % n) + n) % n. Hide __nav when there is one entry or none.
keyboard← / → — previous / next entry. Ignore the keys while focus is in an editable field.
announceA visually hidden aria-live="polite" line: "N of M: eyebrow title" after each step.
product shot<img class="eu-parallax-card__product"> inside __card, after __scene. Framing per entry through CSSOM: --eu-parallax-card-fit-w (default 112%), -fit-x, -fit-y (from centre, % of the card). No product yet: render none; the card is complete without it.
crossfadeOn a step, keep the outgoing shot mounted with __product--out, BEFORE the incoming one in source order. Both animations fill both; no timer is needed. Replace the element (don't swap src) so the animation re-runs.
tiltOn pointermove (fine pointers, never under reduced motion): nx, ny = pointer offset from the card centre over its size (−0.5…0.5). Write --eu-parallax-card-mx/-my = nx/ny, -sx/-sy = (n + 0.5) × 100%, -shine = 0.85, and __card transform: rotateX(−ny·14deg) rotateY(nx·14deg). On pointerleave: clear the transform, mx/my/shine back to 0.
shot throwThe shot overhangs the card, so where the card nearly fills the screen the full throw carries the art off the viewport and it is clipped mid-wing. Measure the room beside the card and write --eu-parallax-card-shot-travel (0…1, default 1) — it scales the shot's parallax only; the card's rotation and the plates behind it stay full.
toggleOptional <button class="eu-parallax-card__check" aria-pressed> with an accessible name naming the entry. On false→true set data-locking for 420ms. __check-hint inside it is opt-in, only while unpressed.
motionCloud drift is CSS. prefers-reduced-motion stops drift, transitions, shine, hint and crossfade in CSS; the consumer skips tilt. Set data-motion="gyro" on the block while a phone's attitude steers the tilt.
